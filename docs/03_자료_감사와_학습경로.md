# G001/G002 — 자료 감사와 학습 경로 설계

이 문서는 현재 코드와 앞으로 공부·구현할 개념을 분리하는 지도다. 수식과 API를 한 번에 외우기보다, 각 단계의 질문 하나씩 확인한다.

## 현재 코드의 결론

감사 당시 저장소에는 **TV-LQR, 선형 Kalman filter, EKF 구현이 없었다.** G002에서 현재 `include/bldc/tv_lqr.hpp`와 `include/bldc/kalman_filter.hpp`를 hardware-free pure domain API로 추가했다. 아래의 `StateEstimator` 설명은 기존 complementary-filter 기반 estimator에만 해당한다.

- IMU gyro 적분과 accelerometer complementary filter로 pitch를 추정한다.
- 좌우 wheel speed를 forward velocity로 변환한다. 현재는 거리/pose를 적분하는 wheel odometry가 아니다.
- VSLAM pose correction을 적용한다.
- IMU 입력의 timestamp와 `dt`, finite 값, angle wrapping을 검사한다. wheel/VSLAM 입력에는 같은 freshness 계약이 아직 없다.

기존 `StateEstimator`는 covariance `P`, process noise `Q`, measurement noise `R`, state transition `A`, measurement model `C/H`, Jacobian, Riccati recursion을 갖고 있지 않다. 새 `kalman_filter.hpp`는 별도 API이며 기존 complementary filter를 Kalman/EKF라고 부르면 안 된다.

현재 control-side에는 CAN decode, command clamp, heartbeat freshness, timeout, fault latch, transmit gate가 있다. default firmware는 receive-only이며, TX-enabled review/tutorial 환경은 별도 검토 경로다. 테스트와 compile target은 hardware를 조작하지 않는다. scalar wheel-balance gain이 있더라도 이것은 state-space LQR gain `K`와 다르다.

## ADHD 친화 학습 순서

이 문서의 **단일 권장 순서**는 제어를 먼저 이해한 뒤 확률적 추정을 연결하는 것이다.

1. **벡터·행렬**: 곱셈, transpose, inverse, symmetric, positive definite를 손으로 계산한다.
2. **시간 이산화**: `x[k+1] = A x[k] + B u[k] + w[k]`, `y[k] = C x[k] + v[k]`의 각 항에 단위를 붙인다.
3. **피드백**: 오차 `e = x - x_ref`, `u = -K e`, clamp와 안전 제한을 분리한다.
4. **제어 가능성/관측 가능성**: 입력으로 상태를 움직일 수 있는지, 센서로 볼 수 있는지 확인한다.
5. **LQR**: `xᵀQx + uᵀRu`를 읽고 Riccati가 미래 비용을 feedback gain으로 압축하는 직관을 잡는다.
6. **finite/time-varying LQR**: horizon 또는 operating point에 따라 `K[k]`가 달라지는 이유를 본다.
7. **TV-LQR·saturation**: gain scheduling/interpolation과 안전 제한을 수학 결과와 별도 계약으로 둔다.
8. **확률과 Gaussian**: 평균, covariance, 상관, process noise와 measurement noise를 구분한다.
9. **Kalman filter**: 먼저 predict, 다음 update; `P`가 불확실성을 표현한다.
10. **EKF**: 비선형 함수의 Jacobian으로 매 주기 local linear model을 만든다. angle wrapping은 별도 실패 조건이다.
11. **코드·테스트**: 수식의 각 항을 타입과 단위로 매핑하고 finite, timestamp, covariance, saturation, stale/fault 경계를 테스트한다.

## G002 구현 범위와 남은 연구 범위

G002 구현은 hardware-free pure domain API로 제한했다.

- **TV-LQR**: 2-state/1-input discrete finite-horizon Riccati recursion을 canonical path로 선택한다. `A=[[1,1],[0,1]]`, `B=[[0.5],[1]]`, `Q=diag(1,0.1)`, `R=[[0.5]]`, terminal `S=Q`, horizon `N=3`을 고정한다. 기대하는 backward gain은 `K[2]≈[0.588235,0.705882]`, `K[1]≈[0.638298,1.106383]`, `K[0]≈[0.595960,1.107891]`이다. gain-table interpolation은 G002 범위에서 제외한다.
- **Linear KF**: `A`, `B`, `C=[1,0]`, `Q=diag(0.01,0.1)`, `R=[[0.25]]`, `x0=[0,0]`, `P0=I`, `u=1`, `z=0.8`, `dt=1`인 2-state/1-measurement fixture를 고정한다. predict 기대값은 `x⁻=[0.5,1]`, `P⁻=[[2.01,1],[1,1.1]]`; Joseph update 기대값은 `innovation=0.3`, `x⁺≈[0.766814,1.132743]`, `P⁺≈[[0.222345,0.110619],[0.110619,0.657522]]`이다. invalid `Q/R/P`, non-monotonic timestamp, non-finite 입력은 거부하고 PSD correction 대신 실패를 반환한다.
- **EKF**: 위 fixture의 transition/measurement와 analytic Jacobian을 callback으로 고정한다. fixed sample period, one predict/update per timestamp, callback `h(x)` innovation, configurable `[-π,π)` wrapping, Jacobian 차원/finite 실패를 명시한다. STM32 HAL, CAN, time source에 의존하지 않는다.
- **안전**: estimator/controller 계산은 command authorization을 우회하지 않는다. stale heartbeat, timeout, fault latch, unarmed, non-finite, out-of-range이면 safe state를 유지한다. receive-only 기본과 compile-time TX gate는 유지한다.
- **단위**: rotor/output, sign, gear ratio, pitch convention은 bench 확인 전 확정하지 않는다.

## 후속 목표 acceptance checklist

### G002 — 도메인 코드 완료 기준

- TV-LQR, KF, EKF가 명확한 public API와 단위/차원 계약을 가진다.
- 정상·경계·오류 경로를 native pure tests로 검증한다.
- canonical fixture의 finite/invalid matrix, covariance symmetry/PSD 거부, `N=3` terminal Riccati step과 위 `K[0..2]` golden 값, fixed sample period, same-epoch timestamp, angle wrap, callback failure, fault/command gate를 검증한다. gain-table interpolation은 이 목표의 테스트 대상이 아니다.
- `native`, `native_tx_gate`에서 hardware 없이 동작하고, `nucleo_f103rb`는 TX-off compile-only로 유지된다.
- 기존 estimator와 새 filter의 역할을 혼동하지 않는다.

### G003 — 공부노트

- 벡터·행렬 → state-space → controllability/observability → LQR/Riccati → finite/time-varying LQR → TV-LQR → Gaussian/Bayes → KF → EKF 순서가 top-down으로 이어진다.
- 각 수식에 변수 의미, 차원, 단위, 직관, 디버깅 질문, 작은 손계산 문제가 있다.
- 각 코드 블록은 public API/test와 링크되고, 반복적인 설명 대신 흐름·실패 원인을 설명한다.
- 공식/대학/교과서/영상 링크와 PDF 한계가 표시된다.
